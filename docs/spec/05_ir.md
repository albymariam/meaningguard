# 05 MG-IR specification (v1)

One IR per sentence and language. The source and the translation use the same schema.

## 1. Top level
| Field | Type | Meaning |
|---|---|---|
| `schema` | string | `"mgir/1"` |
| `lang` | `"en"` or `"hi"` | |
| `text` | string | normalized text |
| `tier` | 1, 2 or 3 | parse tier (03 grammar, recovery note) |
| `clauses` | list of Clause | in sentence order |
| `emotion` | Emotion or null | filled by the emotion module, `null` if unavailable |
| `diagnostics` | list of Diagnostic | lexer flags and parser errors |

## 2. Clause
| Field | Type | Meaning |
|---|---|---|
| `index` | int | position in the sentence |
| `polarity` | `"POS"` or `"NEG"` | clause polarity (02 section 3) |
| `pred_text` | string or null | opaque predicate text, shown in the UI, never compared |
| `facts` | list of Fact | canonical, sorted (C-ORDER) |
| `cond` | Cond or null | present when the clause is part of a conditional |

## 3. Fact (one of)
| `kind` | Fields |
|---|---|
| `QUANT` | `value` (Value), `role`, `approx` (bool) |
| `CHANGE` | `direction`, `from` (Value or null), `to` (Value or null), `delta` (Value or null) |
| `RANGE` | `low` (Value), `high` (Value) |
| `BOUND` | `op`, `value` (Value) |
| `TIMEREL` | `rel`, `anchor` (TIME or DATE value) |
| `NEG` | `scope` (`CLAUSE`, `REL`, `QUANT`), `strength` (`STRONG`, `WEAK`), `target` (Fact or string) |

Every Fact also carries `fp` (fingerprint, 02 section 6), `span` (character offsets in `text`) and
`flags` (list of lexer flags that affected it). `fp` ignores `span` and `flags`.

## 4. Value
`{"type": "MONEY"|"COUNT"|"PERCENT"|"TIME"|"DATE"|"VAGUE", ...type fields...}` with Decimals written
as strings. Example: `{"type":"MONEY","amount":"500000","currency":"INR"}`.

## 5. Cond
`{"op": "IF"|"ELSE", "role": "ANTECEDENT"|"CONSEQUENT", "peer": <clause index>}`.

## 6. Emotion
| Field | Meaning |
|---|---|
| `sentiment` | `positive`, `negative`, `neutral`, or `uncertain` |
| `label` | `joy`, `anger`, `sadness`, `fear`, `neutral`, or `uncertain` |
| `possible_sarcasm` | bool, English source only |
| `confidence` | 0 to 1, from the voting rule |
| `signals` | per-model outputs kept for the UI |
| `votes` | number of agreeing signals |

## 7. Diagnostic
`{"code": str, "severity": "info"|"warning"|"error", "span": [start, end]|null, "message": str}`.
Codes are the lexer flags (01 section 5), parser errors (`SCALE_ORDER`, `UNSUPPORTED_STRUCTURE`),
and the semantic codes in 02 and 06.

## 8. Example (`The price fell from ₹500 to ₹400, so do not pay after Friday.`)
```json
{
  "schema": "mgir/1", "lang": "en", "tier": 1,
  "clauses": [
    {"index": 0, "polarity": "POS", "pred_text": "price fell",
     "facts": [{"kind": "CHANGE", "direction": "FALL",
                "from": {"type": "MONEY", "amount": "500", "currency": "INR"},
                "to":   {"type": "MONEY", "amount": "400", "currency": "INR"}}]},
    {"index": 1, "polarity": "NEG", "pred_text": "pay",
     "facts": [{"kind": "TIMEREL", "rel": "AFTER", "anchor": {"type": "DATE", "weekday": 4}}]}
  ]
}
```

## 9. Invariants (checked by tests)
1. Re-serializing then parsing the JSON gives an identical IR.
2. `fp` depends only on canonical attributes: shuffling sibling facts or changing surface text
   (`5 lakh` vs `500000`) does not change it.
3. A QUANT inside CHANGE, RANGE or BOUND is stored in that node only, not duplicated as a QUANT.
4. `tier == 3` implies every fact is a QUANT or a clause-level NEG.
